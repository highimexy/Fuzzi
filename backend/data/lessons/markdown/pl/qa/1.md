# Systemy Binarne i Hexadecymalne

Aby zrozumieć, jak komputery "myślą", musimy wyjść poza interfejs i zajrzeć w surową logikę bitów i bajtów. System binarny i szesnastkowy to fundamenty całego sprzętu i oprogramowania.

## System Binarny: Język Obwodów

System binarny (dwójkowy) to system liczbowy o podstawie 2. Używa tylko dwóch cyfr: `0` i `1`.

- **0**: Oznacza "wyłączony" (niskie napięcie).
- **1**: Oznacza "włączony" (wysokie napięcie).

Każdy znak, obraz i instrukcja, które widzisz na ekranie, są ostatecznie sprowadzane do sekwencji tych dwóch cyfr.

### Dlaczego nas to obchodzi w QA?

W testowaniu spotkasz system binarny m.in. w:

- **Pakietach sieciowych:** Surowa transmisja danych.
- **Nagłówkach plików:** Identyfikacja typu pliku (np. `89 50 4E 47` dla PNG).
- **Maskach bitowych:** Używanie bitów do reprezentowania flag (np. uprawnienia odczyt/zapis/wykonanie).

## System Szesnastkowy (Hex): Skrót Programisty

Zapisywanie długich ciągów binarnych (`110101011011`) jest żmudne i podatne na błędy. System szesnastkowy (o podstawie 16) rozwiązuje ten problem.

Hex używa cyfr `0-9` oraz liter `A-F`:

- `A` = 10, `B` = 11, `C` = 12, `D` = 13, `E` = 14, `F` = 15.

> **Pro Tip:** Jedna cyfra szesnastkowa reprezentuje dokładnie 4 bity (tzw. "półbajt" lub "nibble"). Dwie cyfry szesnastkowe tworzą 8 bitów, czyli pełny bajt. To sprawia, że jest to standardowy sposób podglądu danych w pamięci lub na dysku.

| Dziesiętny | Binarny  | Hex |
| :--------- | :------- | :-- |
| 0          | 0000     | 0   |
| 10         | 1010     | A   |
| 15         | 1111     | F   |
| 255        | 11111111 | FF  |

## Scenariusz Testowy

Wyobraź sobie endpoint API, który zwraca `status_code` jako maskę bitową.
Jeśli `1` = `ENABLED`, `2` = `LOGGED_IN`, a `4` = `ADMIN`, wartość `5` (binarnie `101`) oznacza, że użytkownik jest `ENABLED` i `ADMIN`.

**Jako QA musisz zweryfikować, czy te maski są stosowane poprawnie.**
